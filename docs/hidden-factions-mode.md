# 窥秘者模式（设计规格）

> 当前阶段：规则锁定与服务端可测试性优先；尚未接入正式牌局入口。

## 已确定规则

- **牌堆**：沿用经典模式的 28 张水果牌 + 3 张经典大猩猩牌。探查是本模式额外的独立组件，不替换、不混入经典牌堆。
- **阵营**：红方、蓝方、窥秘者。红蓝双方各有一名暗桩；暗桩的公开身份属于一方，真实阵营属于另一方。
- **信息**：红/蓝玩家按公开阵营获得对应库存视角；暗桩不能因为真实阵营而获得第二套库存信息。窥秘者可以看到除自己外其他玩家的库存。
- **红蓝胜利**：红方胜利要求蓝方的忠诚成员先达到 7 点怒气；蓝方同理。暗桩自己达到 7 点怒气时，其真实阵营失败，不能通过自我受罚帮助真实阵营。
- **按铃**：暂时不限制每小局按铃次数。每次按铃立即结算当前订单，结算后订单清空，不能反复结算同一批订单。误敲铃仍由按铃者承担处罚；爆单处罚沿用现有规则。
- **暗桩**：没有额外规则权限，可以选择订单、探查、发言、撒谎和按铃；不能直接修改订单、库存、爆单判定或分数。暗桩的限制来自真实胜利条件和个人怒气风险，而不是次数限制或踢出机制。
- **窥秘者猜测**：每小局猜两种水果及其数量。猜中 1 种水果得 1 分；猜中 2 种水果但数量不全准确得 2 分；猜中 2 种水果且两种数量都准确得 3 分。累计 7 分立即胜利。
- **探查**：加入独立探查组件，可查看任意其他玩家的一种水果及具体数量。探查结果只给使用者，是否公开及是否如实报告属于社交推理。探查组件的牌数、补充时机和每小局使用次数在服务端第一版实现前锁定。

## 开发顺序

### 第一阶段：先做可玩、可测的逻辑闭环

1. 增加模式 ID、阵营/暗桩身份分配和服务端私有身份数据。
2. 保持经典水果牌与经典大猩猩牌堆不变；新增独立探查数据结构与服务端私密探查结果。
3. 实现公开阵营库存视角、窥秘者全他人库存视角和暗桩按公开身份取信息。
4. 实现红蓝忠诚成员 7 点胜负、暗桩达到 7 点导致真实阵营失败、窥秘者 1/2/3 分猜测。
5. 保持每小局按铃不限次数，但确保每次按铃只结算并清空当前订单。
6. 为阵营分配、视角权限、探查保密、暗桩自罚失败和窥秘者计分补服务端测试。

### 第二阶段：联机测试与平衡调整

- 用固定牌序和测试房间验证红方、蓝方、暗桩、窥秘者的胜负路径。
- 记录每局小局数、按铃次数、误铃率、暗桩达到 7 的频率和窥秘者平均得分。
- 根据数据调整身份比例、探查频率、窥秘者猜测窗口，不先增加复杂能力。

### 暂缓内容

- 窥秘者专属人物形象和正式美术。
- 小局猜测的动画、特效和完整交互 UI。
- 暗桩专属技能、额外按铃权、怀疑/投票/冻结机制。
- 复杂的阵营进度条、身份揭示动画和完整模式大厅资源。

这些内容必须等第一阶段逻辑测试通过后再做，避免视觉和扩展规则掩盖基础结算错误。
