本文记录封箱经理·克莱德、库存搬运工·巴鲁和临时主管·菲恩的当前图像生成提示词、参考图职责与迭代方式。

三位角色均已正式加入猩风作浪牌组，正式 ID 依次为 `boxing-manager`、`inventory-mover`、`temporary-supervisor`。本文件继续用于后续重绘和精修；重新导出时必须保持已发布 ID、角色设定、标准卡片与表情规格一致。

## 1. 通用生成参数

```text
模型：`gemini-3-pro-image-preview`（可选：`gemini-3.1-flash-image`）
接口：Gemini 原生 `generateContent`
源图尺寸：1024 × 1536
质量：high
构图：2:3 竖向角色卡
```

仓库生成工具：

```bash
IMAGE_MODEL=gemini-3-pro-image-preview \
IMAGE_SIZE=1024x1536 \
IMAGE_QUALITY=high \
node tools/generate-assets.mjs \
  --input <内容参考图> \
  --input <画风参考图> \
  source/characters/<character-id>/<output>.png \
  "<完整提示词>"
```

生成时不要输入已经确认画风错误的 `room-final-v6.png`、`room-final-v7.png` 等中间结果，避免错误画风继续污染后续图片。

## 3. 统一画风提示词

以下画风段应完整加入三位角色的正式生成提示词；这是风格约束，不是可选修饰语。

```text
【目标画风：高质量风格化 3D 动画角色卡】

- 角色拥有厚重、真实的空间体积；头部、胸口、肩膀、手臂和手掌之间有清楚的前后遮挡。
- 轮廓干净、圆润、连续，不使用可见的黑色墨线或手绘描边来分隔形体。
- 视觉重点是角色的脸、手势、服装和职业道具，背景只做支持。

2. 大猩猩物种与面部
- 保持参考图中的同一种大猩猩物种和面部语言。
- 面部宽阔，口鼻部前凸而厚重，眉骨明显，鼻翼清楚，眼睛小而有神。
- 鼻子、嘴唇、脸颊、下巴和额头都是连续的立体曲面，不是平面贴纸或漫画色块。

- 身体毛发是柔软、浓密、哑光的短绒材质，以完整毛发体块呈现。
- 头顶、脸侧和手臂边缘可以有少量自然毛发轮廓，但不要用尖锐线条、排线或漫画笔触画毛发。
- 毛发明暗连续，具有柔和的方向和块面；不要单一纯黑色块，也不要一根根刻画成写实动物毛。
- 面部和手掌皮肤细腻、柔软，有轻微自然的次表面散射和环境遮蔽。
- 不要橡胶皮肤、发亮塑料、黏土、蜡像或毛绒玩具质感。

4. 材质
- 白色衬衫是柔软棉布，有细微褶皱和自然布料反光。
- 紫色经理背心是干净厚实的织物，颜色饱满但不过度发光。
- 单片眼镜和金色链条是细致克制的金属材质，反光小而真实，不抢脸部视觉中心。
- 透明封存盒是清楚的玻璃或透明亚克力，具有边缘反光、折射和与桌面的接触关系，但不要夸张镜面效果。
- 榴莲有清楚的尖刺、黄绿色果皮和真实重量，不能画成普通绿色球体或扁平图标。
- 每种材质靠三维光照、粗糙度和空间遮蔽区分，不靠黑色轮廓线。

5. 光照与颜色
- 使用明亮、温暖、柔和的动画电影级全局照明。
- 阴影宽而柔和，明暗过渡连续自然；使用环境遮蔽塑造眉骨、口鼻、手指、衣领和道具接触处的深度。
- 不使用硬边赛璐璐阴影，不使用强烈戏剧光、镜头光晕或摄影棚高光。
- 参考图的青绿色背景、紫色背心、米白衬衫和深色毛发形成清晰但柔和的色彩关系。
- 基础色饱满、明快、适合派对游戏，不使用霓虹色或过度灰暗的电影调色。

6. 构图与卡面
- 使用 2:3 竖向角色卡构图，角色主体居中，采用完整头肩或半身构图。
- 头顶、下巴、双手、透明封存盒和左上角机制徽章都必须保留安全边距。
- 背景使用干净的青绿色圆角卡面气质，只加入极少量包装工作区暗示。
- 不绘制复杂写实仓库、密集货架、大片纸箱或抢夺角色注意力的背景。
- 左上角机制徽章必须是卡面世界中的实体小物件，有厚度、材质和光照，不是现代扁平 UI。

7. 严格禁止
- 不要二维手绘插画、粗黑轮廓、可见墨线、漫画线稿或均匀矢量描边。
- 不要赛璐璐硬色块、纸张颗粒、印刷噪点、水彩、铅笔、笔刷纹理或复古桌游海报风。
- 不要低幼绘本、日漫、照片写实、电影概念设计或通用 AI 卡通风。
- 不要把角色渲染成另一只大猩猩；必须保持参考图的脸、体型、毛发、服装和单片眼镜。
- 不要文字、数字、乱码、品牌、水印、签名、多余肢体、手指、眼睛、牙齿或重复道具。
```

## 8. 迭代原则

1. 第一轮只输入已确认的 3D 角色与画风基准图，先确认脸、毛发、体积、材质和光照。
2. 画风确认前，不输入二维内容候选图；机制内容优先使用文字描述。
3. 每次只处理一个角色，每轮只增加一个内容层级：核心道具、徽章、订单或局部手部。
4. 内容图只用于人工核对业务关系，不允许其粗描边、赛璐璐、纸张纹理和暗色背景进入生成结果。
5. 内容复杂度与画风冲突时，减少图标和背景细节，优先保证角色与画风一致。
6. 不把多个错误候选同时作为参考图，不继续输入已确认画风错误的中间结果。
7. 候选图片只保存在 `assets/source/characters/`，用户确认前不写入公开素材目录和运行时代码。
8. 每次生成后检查 PNG、RGB、`1024 × 1536` 和完整解码；技术规格通过不等于视觉审核通过。
